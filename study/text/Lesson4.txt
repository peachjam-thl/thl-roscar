Package Management
1.1 Package management

1.1.1 Linux software package
 Ø Linux下的软件包分为两种，分别是 源码包 和 二进制包：

 (1) 源码包：源码包是源代码程序，是由程序员按照特定的格式和语法编写出来的软件包

   l 源码包安装需要经过编译

   l 编译：指从源代码到直接被计算机执行的目标代码的翻译过程，编译器的功能是把源代码翻译为二进制代
     码，让计算机识别并运行

   l 源码包一般包含多个文件，为了方便发布，通常会将源码包做打包压缩处理

 (2) 二进制包：是指源码包经过成功编译之后产生的软件包

   l 二进制包是 Linux 下默认的软件安装包，二进制包有专用的包管理系统

   l DPKG 包管理系统：Debian 和 Ubuntu 的软件包管理工具

   l RPM 包管理系统：Fedora、CentOS、SuSE软件包管理工具
1.1 Package management

1.1.2 Source code package installation
 Ø 源码包：Linux 中最常用的打包压缩格式为“tar.gz”，因此源码包又被称为 Tarball

   1. 找到相应的软件包soft，比如soft.tar.gz，下载到本机某个目录

   2. 打开一个终端，su成root用户

   3. cd soft.tar.gz 所在的目录

   4. tar -zxvf soft.tar.gz #一般会生成一个soft目录

   5. cd soft

   6. ./configure

   7. make

   8. make install

1.1.2 Source code package installation
 Ø 注解：整个安装过程可以分为以下几步：

  1.   取得应用软件：通过下载、购买光盘的方法获得

  2.   解压缩文件：如果是 gz 格式，则可以执行：“tar -zxvf 软件包名”，就可以一步完成解压与解
       包工作。如果不是，则先用解压软件，再执行“tar -xvf 解压后的tar包”进行解包

  3.   阅读附带的 INSTALL 文件、README文件

  4.   执行“./configure”命令为编译做好准备

  5.   执行“make”命令进行软件编译

  6.   执行“make install”完成安装

  7.   执行“make clean”删除安装时产生的临时文件

1.1.5 Install-free package
 Ø   有些软件是不需要安装的，解压缩后可直接运行，假设下载的是firefox.tar.gz，使用方法如下：

     l   打开一个终端，su成root用户

     l   tar -zxvf firefox.tar.gz # 这一步会生成一个叫 firefox 的目录

     l   cd firefox

     l   chmod +x firefox # 设置 firefox 这个程序文件为可运行

     l   执行命令./firefox 即可运行软件

 Ø   每次运行要输入全路径或切换到生成的 firefox 目录里才可执行，在/bin目录下建立一个firefox的软
     链接，则打开一个终端输入 firefox 就可以运行此软件

 Ø   如果要想 firefox 有个菜单项，使用菜单编辑工具，如 Alacarte Menu Editor，也可以到
     /usr/share/applications目录，按照里面其它 *.desktop 文件的格式生成一个自己的 desktop 文件
1.1 Package management

1.1.6 PPA installation
Ø   APT 和 Ubuntu 软件中心都是通过软件源方式安装软件，APT会从每一个软件源（软件仓库）下
    载一个软件包的列表到本地，列表中提供有软件源所包含的可用软件包的信息

Ø   通常从 Ubuntu 官方仓库中获取软件，考虑到稳定性，Ubuntu 官方仓库收录的软件比较正式，
    版本相对滞后

Ø   对于没有收录到 Ubuntu 官方仓库的软件，可以通过 PPA(Personal Package Archive)非正式的
    软件仓库进行安装，其格式如下：

    $ sudo add-apt-repository ppa:user/ppa-name

    $ sudo apt-get update

    $ sudo apt-get install ppa-name
1.1 Package management

1.1.6 PPA installation
Ø   Ubuntu 使用文本文件 /etc/apt/sources.list 来保存软件包的安装和更新源的地址。另外与该文
    件功能相同的是 /etc/apt/sources.list.d/目录下的 list 文件。为在单独文件中写入安装源的地址
    提供了一种方式，通常用来安装第三方软件

Ø   执行 apt-get update 就是同步(更新) /etc/apt/sources.list 和 /etc/apt/sources.list.d 目录
    下的 list 文件的软件源的索引，以获取最新的软件包

Ø   一个典型的软件源：deb http://cn.archive.ubuntu.com/ubuntu/ utopic-backports main
    restricted universe multiverse，共有3个字段，字段间用空格分隔：

    l   第1个字段位于行首，用于指示软件包的类型。Debian类型的软件包使用 deb 或者 deb-src，分别表示
        直接通过 .deb 文件进行安装或者通过源文件的方式进行安装

    l   第2个字段定义URL，表示提供软件源的CD-ROM、HTTP或FTP服务器的URL地址
1.1 Package management

1.1.6 PPA installation
Ø   第3个字段定义软件包的发行版本或分类，用于帮助 APT 命令遍历软件库。这些分类是用空格隔开的字符串，每
    个字符串分别对应相应的目录结构：

      l   main： Canonical支持的开源软件，大部分都是从这个分支获取的

      l   universe：社区维护的开源软件

      l   restricted：由设备生产商专有的设备驱动软件

      l   multiverse：受版权或者法律保护的相关软件

      l   security：重要的安全更新

      l   updates：推荐的一般更新

      l   proposed：预览版的更新

      l   backports：无支持的更新，这种更新通常还存在一些bug

What is ROS?
2.1 Philosophy of ROS

              ROS = Robot Operating System

 The Robot Operating System (ROS) is a flexible framework for
 writing robot software. It is a collection of tools, libraries, and
 conventions that aim to simplify the task of creating complex
 and robust robot behavior across a wide variety of robotic
 platforms.




                                                    来源：https://www.ros.org/about-ros/
2.1 Philosophy of ROS




 Plumbing：通讯机制（实现ROS不同节点之间的交互）

 Tools：工具软件包（ROS中的开发和调试工具）

 Capabilities：机器人高层技能（ROS某些功能的集合，比如：导航）

 Ecosystem：机器人生态系统（跨地域、跨软件与硬件的ROS联盟）

Ø GNU是"GNU'S Not UNIX“的缩写，其含义是开发出一套与UNIX相似而不是UNIX的系统

Ø GNU包含3个协议条款：GPL、LGPL、GFDL。GPL是"General Public License“的缩写，它是GNU

 1.1 Ubuntu file and directory

1.1.1 Ubuntu file
Ø 文件是 Linux 操作系统处理信息的基本单位，所有软件都以文件形式进行组织（一切皆文件），例如：

  ü Linux 下的可执行程序是一个二进制文件

  ü 程序启动时候需要加载一些配置文件，程序运行时会产生一些日志文件或者中间文件，这些文件是 文本文件

  ü 如果程序产生的日志需要打印到控制台上，需要用到标准输出文件，即 stdout 文件

  ü 各程序之间进行数据交互，例如一个程序的输出是另一个程序的输入，需要用到 管道文件

  ü 不同的程序之间通信利用 socket 进行通信，在 socket 编程的时候就需要操作 socket 文件

  ü 运行中的程序可能需要访问一些硬件设备，每个硬件设备在 Linux 上也是映射成了 设备文件

  ü 文件本身需要有地方存储，存储文件的对象叫文件夹(即目录)，目录 自身也是一种文件
 1.1 Ubuntu file and directory

1.1.1 Ubuntu file
Ø Naming convention：

   ü 单一文件或目录的最大容许文件名为 255 个字符

   ü 包含完整路径名称及根目录（/）的完整文件名最长为 4096 个字符

   ü 文件名严格区分大小写

   ü 文件名可以包含空格等特殊字符，但必须使用引号

   ü 不可以包含 “/” 字符，还应避免特殊字符(通配符)：* ? > < ; & ! [ ] | \ ' " ` ( ) { }

   ü 同类文件应使用同样的后缀或扩展名
1.1 Ubuntu file and directory

1.1.1 Ubuntu file
Ø Linux 文件无论是一个程序、一个文档、一个数据库，或者是一个目录，操作系统都会赋予文件相
 同的结构，具体包括以下两部分：

  l 索引节点：又称 I 节点。在文件系统结构中，包含有关相应文件信息的记录，这些信息包括文件权限、文
    件所有者、文件大小等

  l 数据：文件的实际内容，可以是空的，也可以非常大，并且有自已的结构

Ø Linux 文件分为以下4种类型：普通文件、目录文件、设备文件、链接文件

  l 普通文件：

    • 普通文件也称为常规文件，包含各种长度的字符串。内核对这些文件没有进行结构化， 只是作为有序
      的字符序列把它提交给应用程序，由应用程序自己组织和解释这些数据

    • 普通文件包括文本文件、数据文件和可执行的二进制程序等
1.1 Ubuntu file and directory

1.1.1 Ubuntu file
 l 目录文件：

   • 目录文件是一种特殊文件，利用它可以构成文件系统的分层树形结构。目录文件也包含数据，但与普

  Ø 第2层则针对 /usr 及 /var 这两个目录的子目录应该放什么文件

Ø FHS仅定义出最上层（/）及子层（/usr、/var）的目录内容应该要放置的文件，在其他子目录层级内

1.2 User group

1.2.1 Group identities
文件访问者身份是指文件权限设置所针对的用户和用户组，共有以下3种类型：

 Ø 所有者：每个文件都有它的所有者，又称属主，简写为 u。默认情况下，文件的创建者即为其所
  有者。所有者对文件具有所有权，是一种特别权限

 Ø 所属组：指文件所有者所属的组，简称属组，简写为 g，可为该组指定访问权限。默认情况下，
  文件的创建者的主要组即为该文件的所属组

 Ø 其他用户：指文件所有者和所属组，以及 root 之外的所有用户，简写为 o。通常其他用户对文
  件拥有最低的权限，甚至没有权限
1.3 Access mode

1.3.1 Access rights
对于每个文件，针对上述3类身份的用户可指定以下3种不同级别的访问权限：

Ø 读：读取文件内容或者查看目录

Ø 写：修改文件内容或者创建、删除文件

Ø 执行：执行文件或者允许使用cd命令进入目录

 1.4 The tools

1.4.1 chown
Ø 文件所有者可以变更，即将所有权转让给其他用户，只有root才有权变更所有者

Ø 使用 chown 命令变更文件所有者，使其他用户对文件具有所有权，基本用法如下：

     chown [选项] [新所有者] 文件列表

     备注：使用选项-R进行递归变更，即目录连同其子目录下的所有文件的所有者都变更

Ø 执行 chown 命令需要 root 权限，需要使用 sudo 命令

Ø 举例说明：

   $ sudo chown wang news    # 将 news 的所有者改为 wang
 1.4 The tools

1.4.2 chgrp
Ø 使用 chgrp 命令可以变更文件的所属组，基本用法如下：

      chgrp [选项] [新的所属组] 文件列表

Ø 亦可使用 chown 命令变更文件所属组，使其他用户对文件具有所有权，基本用法如下：

      chown [选项] [新所有者]:[新的所属组] 文件列表

      备注：使用选项-R进行递归变更，即目录连同其子目录下的所有文件的所属组都变更

Ø 执行 chgrp 命令需要 root 权限，需要使用 sudo 命令

Ø 举例说明：

  $ sudo chgrp shentong fenti   # 改变文件 fenti 所属组为 shentong
 1.4 The tools

1.4.3 chmod
Ø root 和文件所有者可以修改文件访问权限，使用 chmod 命令来修改文件权限，基本用法如下：

     chmod [选项] 模式 文件名

Ø 模式是文件权限的表达式，有字符和8进制两种表示方法；

Ø 执行 chmod 命令需要 root 权限，需要使用 sudo 命令

  1. 文件权限用字符表示：

     •   “+”表示增加某种权限，”-”表示撤销某种权限，”=”表示指定某种权限（同时会取消其他权限）

     •   对于用户类型，所有者、所属组和其他用户分别用字符 u、g、o 表示，全部用户（包括3种用户）则用
         a 表示

     •   权限类型用r（读）、w（写）和 x（执 行）表示
1.4 The tools

1.4.3 chmod
Ø 举例说明：

$ sudo chmod g+w, o+r /home/ros/myfile   # 给所属组用户增加写权限，给其他用户增加读权限

$ sudo chmod go-r /home/ros/myfile       # 同时撤销所属组和其他用户对该文件的读权限

$ sudo chmod a=rx /home/ros/myfile       # 对所有用户赋予读和执行权限


  2. 文件权限用数字表示：

      •   将权限读（r ）、写（w ）和执行（x ）分别用数字 4、2 和 1 表示，没有任何权限则表示为 0

      •   每一类用户的权限用其各项权限的和表示（结果为数字0~7）,依次为所有者（u）、所属 组（g）和其他用
          户（O）的权限

1.4.3 chmod

  ü 例一：

  754 表示所有者、所属组和其他用户的权限依次为[4+2+1]、[4+0+1]、[4+0+0]，转化为字符表示就
  是：rwxr-xr--

1.1 Package management

1.1.1 Linux software package
 Ø Linux下的软件包分为两种，分别是 源码包 和 二进制包：

 (1) 源码包：源码包是源代码程序，是由程序员按照特定的格式和语法编写出来的软件包

   l 源码包安装需要经过编译

   l 编译：指从源代码到直接被计算机执行的目标代码的翻译过程，编译器的功能是把源代码翻译为二进制代
     码，让计算机识别并运行

   l 源码包一般包含多个文件，为了方便发布，通常会将源码包做打包压缩处理

 (2) 二进制包：是指源码包经过成功编译之后产生的软件包

   l 二进制包是 Linux 下默认的软件安装包，二进制包有专用的包管理系统

   l DPKG 包管理系统：Debian 和 Ubuntu 的软件包管理工具

   l RPM 包管理系统：Fedora、CentOS、SuSE软件包管理工具
1.1 Package management

1.1.2 Source code package installation
 Ø 源码包：Linux 中最常用的打包压缩格式为“tar.gz”，因此源码包又被称为 Tarball

   1. 找到相应的软件包soft，比如soft.tar.gz，下载到本机某个目录

   4. tar -zxvf soft.tar.gz #一般会生成一个soft目录

   5. cd soft

1.1.6 PPA installation
Ø   APT 和 Ubuntu 软件中心都是通过软件源方式安装软件，APT会从每一个软件源（软件仓库）下
    载一个软件包的列表到本地，列表中提供有软件源所包含的可用软件包的信息

Ø   通常从 Ubuntu 官方仓库中获取软件，考虑到稳定性，Ubuntu 官方仓库收录的软件比较正式，
    版本相对滞后

Ø   对于没有收录到 Ubuntu 官方仓库的软件，可以通过 PPA(Personal Package Archive)非正式的
    软件仓库进行安装，其格式如下：

    $ sudo add-apt-repository ppa:user/ppa-name

    $ sudo apt-get update

    $ sudo apt-get install ppa-name
1.1 Package management

1.1.6 PPA installation
Ø   Ubuntu 使用文本文件 /etc/apt/sources.list 来保存软件包的安装和更新源的地址。另外与该文
    件功能相同的是 /etc/apt/sources.list.d/目录下的 list 文件。为在单独文件中写入安装源的地址
    提供了一种方式，通常用来安装第三方软件

Ø   执行 apt-get update 就是同步(更新) /etc/apt/sources.list 和 /etc/apt/sources.list.d 目录
    下的 list 文件的软件源的索引，以获取最新的软件包

Ø   一个典型的软件源：deb http://cn.archive.ubuntu.com/ubuntu/ utopic-backports main
    restricted universe multiverse，共有3个字段，字段间用空格分隔：

    l   第1个字段位于行首，用于指示软件包的类型。Debian类型的软件包使用 deb 或者 deb-src，分别表示
        直接通过 .deb 文件进行安装或者通过源文件的方式进行安装

    l   第2个字段定义URL，表示提供软件源的CD-ROM、HTTP或FTP服务器的URL地址
1.1 Package management

1.1.6 PPA installation
Ø   第3个字段定义软件包的发行版本或分类，用于帮助 APT 命令遍历软件库。这些分类是用空格隔开的字符串，每
    个字符串分别对应相应的目录结构：

      l   main： Canonical支持的开源软件，大部分都是从这个分支获取的

      l   universe：社区维护的开源软件

      l   restricted：由设备生产商专有的设备驱动软件

      l   multiverse：受版权或者法律保护的相关软件

      l   security：重要的安全更新

      l   updates：推荐的一般更新

      l   proposed：预览版的更新

      l   backports：无支持的更新，这种更新通常还存在一些bug
