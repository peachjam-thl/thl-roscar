 1.1.1 Overview
Ø C++ 是 C 语言的加强版，C++ 语言最初被称为“带类的C”，由计算机程序员 Bjarne Stroustrup
 于1979年开发

Ø 和 C 一样，C++ 也是一种需要被编译的语言，它需要一个编译器将源代码转换为可执行代码

Ø Ubuntu自带一个内置的 C/C++编译器，称为 GCC/G++

Ø GCC 由 Richard Stallman 为 GNU 项目编写的（创立自由软件 GNU、Emacs 文字编辑器、GCC编
 译器、GDB调试器、GPL协议）

Ø GCC 代表 GNU 编译器的集合，其可以编译 C、C++、Objective-C、Fortran、Ada 和 Go 等多种
 语言，以及这些语言的库

1.1.3 C++中OPP概念
Ø 类访问修饰符

   l 上述代码中有 public: 关键字，其被称为成员访问修饰符

   l 通过设置成员访问修饰符，可以限制在类内部定义的函数的使用范围

   l 类中有3种访问修饰符：

     •   public(共有)：一个公有成员可以从类以外的任何地方被访问。用户可以直接访问公共变量，不需
         要编写其他辅助函数

     •   private(私有)：使用该修饰符号的成员变量或函数，不能从类的外部被查看或者访问。只有类和
         友元函数可以访问私有成员

     •   protected(保护)：访问权限类似于private，不同的是其子类/派生类可以访问其成员

   l 成员修饰符可以帮助用户将变量分组，这些变量在类中保持可见或者隐藏

1.1.3 C++中OPP概念
Ø C++中 Inheritance 的使用

   l Inheritance(继承)是 OPP 中的一个重要概念

   l 如有已有两个或多个类，并且在新建的类中希望使用这些已有类中的函数，可以使用
     Inheritance 属性

   l 用户可以在新类中重用现有类中的函数，继承现有类的新类，称为派生类

   l 类可以通过 public、private 和 protected 来继承

      • public inheritance： 当派生自 public 基类时，基类的 public 成员成为派生类的
        public 成员，并且基类的 protected 成员成为派生类的 protected 成员；基类的
        private 成员不能在派生类中访问，但可以通过基类的 public 和 protected 成员函数
        的调用来访问
1.1 Getting started with C++

1.1.3 C++中OPP概念
   • private inheritance：当派生自 private 基类时，基类的 public 和 protected 成员成
     为派生类的 private 成员
   • protected inheritance：当使用 protected 基类继承时，基类的 public 和 protected
     成员成为派生类的 protected 成员

1.1.4 建立一个C++工程
Ø 建立一个Linux makefile
   l Linux makefile 提供了一种组织、编译多个源代码文件的方法
   l 以下为上述代码的 makefile 文件
    CC = g++
    CFLAGS = -c
    SOURCES = main.cpp add.cpp
    OBJECTS = $(SOURCES:.cpp=.o)
    EXECUTABLE = main
    all: $(OBJECTS) $(EXECUTABLE)
    $(EXECUTABLE) : $(OBJECTS)
                      $(CC) $(OBJECTS) -o $@
    .cpp.o: *.h
             $(CC) $(CFLAGS) $< -o $@
    clean :
             -rm -f $(OBJECTS) $(EXECUTABLE)
    .PHONY: all clean

1.1.1 Overview： http://wiki.ros.org/roslaunch/
Ø roslaunch 是一个工具，可以通过 SSH 在本地和远程轻松启动多个 ROS 节点，以及在参数
  服务器上设置参数

Ø roslaunch 接收一个或多个 XML 配置文件（带有 .launch 扩展名），这些文件指定要设置
  的参数和要启动的节点，以及它们应该在哪些机器上运行

Ø rosluanch 的语法：

  $ roslaunch package_name file.launch
1.1 Rosluanch format

1.1.2 Roslaunch XML： http://wiki.ros.org/roslaunch/XML
Ø roslaunch tag reference：
    <launch>             Root tag
    <node>               Launch a node
    <machine>            Declare a machine to use for launching
    <include>            Include other roslaunch files
    <remap>              Declare a name remapping
    <env>                Specify an environment variable for launched nodes
    <param>              Set a parameter on the Parameter Server
    <rosparam>           Set ROS parameters for the launch using a rosparam file
    <group>              Group enclosed elements sharing a namespace or remap
    <test>               Launch a test node
    <arg>                Declare an argument

  Ø 两种使用方法：

   <node pkg="package-name" type="node-name" name="name"></node>

2. <node>： 指定需要启动的 ROS 节点，用于启动和关闭节点

  pkg="mypackage"→Package of node, 功能包名称

  type="nodetype" →Node type. There must be a corresponding executable with the same name, 节点名称

  name="nodename" →Node name. NOTE: name cannot contain a namespace. Use the ns attribute
  instead, 节点命名

  args="arg1 arg2 arg3"(optional) →Pass arguments to node, 传递节点参数

  machine="machine-name"(optional, see <machine>) →Launch node on designated machine

  respawn="true"(optional, default: False)→Restart the node automatically if it quits

  respawn_delay="30" (optional, default 0) New in ROS indigo→If respawn is true, wait respawn_delay
  seconds after the node failure is detected before attempting restart

  required="true"(optional)→If node dies, kill entire roslaunch

3. <machine>：声明了一台可以运行 ROS 节点的机器。 如果在本地启动所有节点，则不需要此标签。
其主要用于为远程机器声明 SSH 和 ROS 环境变量设置，也可以使用它来声明有关本地机器的信息


4. <include>：将另一个 roslaunch 文件导入当前文件。它将在文档的当前范围内导入，包括
<group> 和 <remap> 标签。包含文件中的所有内容都将被导入


5. <remap>：用于节点映射。对于有关特定 ROS 主题的消息，该消息通常只发送到一组节点，其他
节点无法接收该消息。这种情况，可以进行重新映射，以便新节点在认为订阅 /different_topic 时最
终订阅 /needed_topic。<remap>基本语法为：



   <remap from="/different_topic" to="/needed_topic"/>
1.1 Rosluanch format

1.1.2 Roslaunch XML： http://wiki.ros.org/roslaunch/XML/remap
5. <remap>：用于节点映射

 remap attributes
   from="original-name"→Remapped topic: name of the ROS topic that you are
 remapping FROM.
    to="new-name"→Target name: name of the ROS topic that you are pointing the
 from topic TO.

 Ø 举例：

  假定一个节点它订阅了“chatter”主题，但只有一个发布到“hello”主题的节点。它们是相
  同的类型，此时希望将“hello”主题传输到需要“chatter”的新节点中。 可以使用此重新映
  射执行此操作：

  <remap from="chatter" to="hello"/>
1.1 Rosluanch format

1.1.2 Roslaunch XML
5. <remap>：用于节点映射

 Ø 注意：

   1. 重映射适用于重映射之后的行。在任何重映射行之前启动的节点不受影响

   2. 重映射会影响节点订阅或发布的主题。但是，通常重映射是在订阅节点上完成的，这意
     味着它实际上是在订阅重映射的主题。因此，任何发布节点最终都会通过发布到 remap
     命令的 to 字段中指定的主题来将它们的消息发送到该节点！

6. <env>：允许在启动的节点上设置环境变量。 此标签只能在 <launch>、<include>、<node>
或 <machine> 标签的范围内使用。 当它在 <launch> 标签内使用时，<env> 标签只适用于之后声
明的节点。 一些环境变量可以在 Environment Variables 中找到


7. <param>：定义了要在参数服务器上设置的参数，相当于命令行中的 rosparam set 。可以指定文
本文件、二进制文件或命令属性来设置参数的值。<param> 标签可以放在 <node> 标签内，在这种
情况下，参数被视为私有参数

9. <group>：用于节点分组，其可以更轻松地将设置应用于一组节点。 它有一个 ns 属性，可将节点
组推送到单独的命名空间中。还可以使用 <remap> 标签在整个组中应用重新映射设置


Ø Attributes：
   l ns="namespace" (optional)→Assign the group of nodes to the specified namespace. The
      namespace can be global or relative, though global namespaces are discouraged.
   l clear_params="true|false" (optional)→Delete all parameters in the group's namespace
      before launch. This feature is very dangerous and should be used with caution. ns must be
      specified.

9. <group>：相当于顶级的 <launch> 标签，只是作为其中标签的容器。 意味着可以使用
任何标签，就像通常在 <launch> 标签中使用一样


9. <group>：可包含 <node>、<param>、<remap>、<machine>、<rosparam>、
