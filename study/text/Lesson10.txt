1.2 Custom message type

1.2.1 Overview

 Ø 在 ROS 通信协议中，数据载体是一个重要组成部分

 Ø ROS 中通过 std_msgs 封装了一些原生的数据类型，比如：String、Int32、Int64、
   Char、Bool、Empty

 Ø String数据只包含一个 data 字段，结构的单一意味着功能上的局限性，当传输一些复
   杂的数据，String由于描述性较差而显得力不从心，这种场景下可以使用自定义的消息
   类型

  l int8, int16, int32, int64 (或者无符号类型: uint*)

  l ROS中还有一种特殊类型：Header，标头包含时间戳和 ROS 中常用的坐标帧信息。

2.5 Additional statement

2.5.1 Matters needing attention
 Ø 执行：
    1. 需要先启动服务：rosrun 包名 服务
    2. 然后再调用客户端：rosrun 包名 客户端 参数1 参数2


 Ø 结果：会根据提交的数据响应相加后的结果


 Ø 注意：如果先启动客户端，那么会导致运行失败


 Ø 解决方案：在客户端发送请求前添加（二选一）：
    1. client.waitForExistence();
    2. ros::service::waitForService("AddInts");
    3. 这是一个阻塞式函数，只有服务启动成功后才会继续执行

1.2.2 What is ROS
Ø ROS是一个适用于机器人的元操作系统，操作系统是用来管理计算机硬件与软件资源，并提供一些公用的服务的
  系统软件
  •   计算机操作系统将计算机硬件封装起来，应用软件运行在操作系统之上，提高软件开发效率

  •   ROS是对机器人的硬件进行封装，不同的机器人、传感器在ROS里可以用相同的方式表示（topic等），供
      上层应用程序（运动规划等）调用




                                                     来源：qRobotics
1.2 Background

1.2.2 What is ROS
Ø ROS是一种跨平台模块化软件通讯机制

  •   ROS用节点（Node）的概念表示一个应用程序，不同 node 之间通过事先定义好格式的消息（Topic），
      服务（Service），动作（Action）来实现连接

  •   基于这种模块化的通讯机制，开发者可以很方便地替换、更新系统内的某些模块；也可以用自己编写的节点
      替换ROS的个别模块，十分适合算法开发




                                                       来源：qRobotics
1.2 Background

1.2.2 What is ROS
Ø ROS是一系列开源工具，ROS为开发者提供了一系列非常有用的工具，可以极大的提高开发效率

  •   rqt_plot：可以实时绘制当前任意Topic的数值曲线

  •   rqt_graph：可以绘制出各节点之间的连接状态 和正在使用的 Topic 等

  •   TF：TF是 Transform 的简写，通过它可以实时计算各连杆坐标系的位姿，以及两个坐标系的相对位置

  •   Rviz：强大的 3D 可视化工具，可以显示机器人模型、3D电影、文字图标、很方便二次开发

  •   Gazebo：一款优秀的开源仿真平台，可以实现动力学仿真、传感器仿真等，已被 ROS 集成

  •   OpenCV：机器视觉开源项目，ROS提供了 cv_bridge，可以将 OpenCV 的图片与 ROS 的图片格式相互转换

  •   OMPL：最著名的运动规划开源项目，已经成了 MoveIt 的一部分

1.2 Background

1.2.2 What is ROS
Ø ROS自身开发的优秀的算法和库：

  •   ORK：物体识别与位姿估计开源库，包含LineMod等算法

  •   PCL：开源点云处理库，原本是从ROS中发展起来的，后来由于太受欢迎，为了让非ROS用户也能用，单独成立了
      一个PCL的项目

  •   Gmapping：由OpenSlam项目继承过来（后来发展和改动较大），利用gmapping可以实现laser-based
      SLAM，快速建立室内二维地图

  •   Localization：基于扩展卡尔曼滤波（EKF）和无迹卡尔曼滤波（UKF）的机器人定位算法，可以融合各种传感器

1.3.4 ROS package
Ø 功能包(package)：实现特定功能的软件包，功能包中包括：功能包清单、消息、服务、代码、其他

  l 功能包是 ROS 中整理和组织软件的主要单元，也是 ROS 中能够建立和分享的最小单元

  l 功能包中包含ROS节点、ROS程序库、数据集、配置文件、可执行文件等

  l 功能包清单(package manifest)：

     • 功能包清单是一个名为 package.xml 的 XML 文件，其必须位于功能包文件夹中

     • 功能包清单中列举了功能包的相关信息，包括功能包名称、版本、作者、开源许可、依赖关系等

  l 消息类型(message type)：

     • 消息是指，一个 ROS 节点发送到其他 ROS 节点的信息，节点间通过将消息发布到话题来实现异步通信，也
       指 ROS 服务中的请求和响应消息

     • 消息位于所在功能包下的 msg 文件夹中，扩展名为.msg，
   1.3 The filesystem level                 turtlesim功能包结构

   l 服务类型(service type)：

       • 定义了 ROS 中由每个 ROS 节点提供的关于服务请求和响应
         的数据结构

       • ROS节点通过调用系统服务来同步交换请求和响应消息

Ø 依赖项：功能包可以有六种类型的依赖项
  •   Build Dependencies specify which packages are needed to build this package. This is the
      case when any file from these packages is required at build time. This can be including
      headers from these packages at compilation time, linking against libraries from these
      packages or requiring any other resource at build time (especially when these packages are
      find_package()-ed in CMake). In a cross-compilation scenario build dependencies are for
      the targeted architecture.

  •   Build Export Dependencies specify which packages are needed to build libraries against this
      package. This is the case when you transitively include their headers in public headers in
      this package (especially when these packages are declared as (CATKIN_)DEPENDS in
      catkin_package() in CMake).

  •   Execution Dependencies specify which packages are needed to run code in this package.
      This is the case when you depend on shared libraries in this package (especially when these
      packages are declared as (CATKIN_)DEPENDS in catkin_package() in CMake).

  •   Build Tool Dependencies specify build system tools which this package needs to build
      itself. Typically the only build tool needed is catkin. In a cross-compilation scenario build

1.1.1 Overview： http://wiki.ros.org/msg
 Ø ROS 使用简化的 消息描述语言 来描述 ROS 消息类型（也称为消息）

 Ø ROS消息的作用是描述节点发布的数据值

 Ø 消息描述存储在 ROS 软件包的 msg 文件夹下，以 .msg 为扩展名

 Ø 消息类型有2种方式：字段(Fields) 和 常量(Constants)

   • 字段：定义了在消息中传输的数据类型，包含字段类型(Field Type)和字段名称(Field
     Name)2部分，如 int32 x、float32 y、string s 等

   • 常量：定义了可用于解释这些字段的值

 Ø 每个字段由一个字段类型和一个字段名称组成，用空格分隔，其语法格式为：

   fieldtype1 fieldname1   Ø 举例：
                              int32 x
   fieldtype2 fieldname2      int32 y
1.1 ROS Message

1.1.2 Fields——Field Type
 Ø 字段类型可以是以下四种之一：

   a)   内置类型，例如“float32 pan”或“string name”

   b) 自定义的消息描述的名称，例如“geometry_msgs/PoseStamped”

   c)   上述的固定或可变长度数组（列表），例如“float32[] ranges”或“Point32[10] points”

   d) 特殊的 Header 类型，该类型映射到 std_msgs/Header


 Ø 嵌入其他消息描述时，如果在同一个功能包中，类型名称可能是相对的（例如“Point32”）；
  否则它必须是完整的消息类型（例如“std_msgs/String”）。 此规则的唯一例外是 Header

 Ø 注意：在构建自己的消息类型时，不得使用内置类型或 Header 的名称

1.1.2 Fields——Field Name
Ø 字段名称决定了如何在目标语言中引用数据值

   l 例如，一个名为“pan”的字段名称在 Python 中将被引用为“obj.pan”，假设“obj”是存储消息的变量


Ø 字段名称需要由消息生成器翻译成多种目标语言，因此

   l 将字段名称限制为字母字符后跟字母数字和下划线的任意混合，即 [a-zA-Z][a-zA-Z1-9_]*

   l 避免使用与常用语言中的关键字相对应的字段名称

2.5 Additional statement

2.5.1 Matters needing attention
 Ø 执行：
    1. 需要先启动服务：rosrun 包名 服务
    2. 然后再调用客户端：rosrun 包名 客户端 参数1 参数2


 Ø 结果：会根据提交的数据响应相加后的结果


 Ø 注意：如果先启动客户端，那么会导致运行失败


 Ø 解决方案：在客户端发送请求前添加（二选一）：
    1. client.waitForExistence();
    2. ros::service::waitForService("AddInts");
    3. 这是一个阻塞式函数，只有服务启动成功后才会继续执行
